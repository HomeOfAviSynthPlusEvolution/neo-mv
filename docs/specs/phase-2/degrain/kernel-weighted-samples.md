# Weighted temporal block samples

Inputs: the current level-zero Super block C, ordered reference fields and available flags, each available reference's Super image, render block geometry, and [per-plane normalized weights](kernel-reference-weights.md). Output: a generated block q in the render sample type. All image inputs have matching logical geometry and sample format, but their positive row strides may differ.

Sample C from Super[n]'s integer phase at the block origin. For each available reference r, sample Rr using its unmodified (vx,vy) and the [render sampling map](../compensate/kernel-block-sampling.md). No time scaling, field adjustment, motion search or error recomputation occurs. For an unavailable reference define its mathematical Rr=C and Vr=0; no reference image is required.

Geometry admission covers all public vectors in all processed planes, independently of weights. A zero Vr for an available reference does not authorize an invalid input field or unsafe geometry. Reference sample values used in the scalar expression must be finite for float inputs.

## Integer samples

For each coordinate in the generated block, with Vc+sum(Vr)=256,

$$q=\left\lfloor\frac{128+V_c C+\sum_{r=0}^{2R-1}V_rR_r}{256}\right\rfloor.$$

Use exact sufficiently wide products and sums. For valid b-bit samples q is in [0,2^b-1]; no range remapping or per-reference rounding occurs. The weights are constant across the block for this plane.

## Float samples

Start z0=fl32(C*Vc). In vectors input order r=0,...,2R-1 compute

$$z_{r+1}=\operatorname{fl32}(z_r+\operatorname{fl32}(R_rV_r)),\qquad q=\operatorname{fl32}(z_{2R}/256).$$

The scalar expression includes zero-weight terms. No +128 or clipping to [0,1] is applied. All intermediates must remain finite. An optimized path may avoid loads only when it preserves the specified result and validation behavior; signed-zero outcomes are those of the stated arithmetic.

Feed these already-rounded block samples to [composition](../compensate/kernel-overlap-composition.md), then apply [change limiting](kernel-change-limit.md). Unprocessed planes are not generated by this kernel; the plugin copies them from clip[n]. Inputs are immutable; output and scratch cannot alias input images or another call's writable storage.

## Examples

- Vc=86,V0=V1=85, C=100,R0=80,R1=140: integer q=floor((128+8600+6800+11900)/256)=107. Float q=106.640625.
- Vc=129,V0=127,V1=0, C=100,R0=80 gives integer q=90 and float q=90.078125.
- All references unavailable give Vc=256. Without overlap, ordinary finite centre samples pass unchanged; output still comes from Super[n], not necessarily clip[n].
- C=-0 in float and an available R0=+1 with V0=0 may change the generated zero to +0 after the specified addition. Copying the centre bit pattern is not a universal replacement for the arithmetic.
- YUV420, p=2, vx=-1 at x=0 samples a reference half a chroma pixel left. The analysis-error kernel's truncating chroma conversion would choose a different sample and is not used here.
